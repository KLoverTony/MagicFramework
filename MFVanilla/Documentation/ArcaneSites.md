# MFVanilla Arcane Sites

This document tracks the current player-facing arcane mission site system for MFVanilla. The implementation lives primarily in `Source/Core/ArcaneCacheSite.cs`, with XML in `Defs/Sites/Parts/MFV_ArcaneCacheSite.xml` and storyteller incidents in `Defs/IncidentDefs/MFV_ArcaneMissionIncidents.xml`.

## Current Mission Set

| Mission | IncidentDef | SitePartDef | Earliest day | Refire | Distance | Threat floor | Timeout | Reward profile |
|---------|-------------|-------------|--------------|--------|----------|--------------|---------|----------------|
| Arcane Cache | `MFV_ArcaneCacheMission` | `MFV_ArcaneCache` | 8 | 18 days | 4-18 tiles | 250 points | 18 days | Normal cache, with threat-gated profile variants |
| Ruined Sanctum | `MFV_RuinedSanctumMission` | `MFV_RuinedSanctum` | 22 | 28 days | 5-20 tiles | 500 points | 22 days | Ruined sanctum profile with broken walls and side rooms |
| Sealed Vault | `MFV_SealedVaultMission` | `MFV_SealedVault` | 45 | 45 days | 8-24 tiles | 1200 points | 28 days | Deep iron vault profile with grand chest |

All three missions use `IncidentDef` entries targeted at `Map_PlayerHome`. Each incident creates a world `Site` through `SiteMaker`, sends a positive event letter, registers an expiry timer, and blocks duplicate active sites of the same `SitePartDef`.

The expiry state is stored in `WorldComponent_ArcaneCacheMissions`. Expired mission sites are removed if they have not generated a map; sites with an active map are treated as resolved and removed from expiry tracking.

## Site Generation

Arcane mission maps are generated by `GenStep_ArcaneCache`. Despite the class name, it is now a reusable profile-driven site generator for cache, vault, and sanctum style locations.

The generator supports:

- circular or rectangular primary rooms
- deterministic wall material selection from profile options
- a reward chest selected by profile
- weighted, threat-gated defender selection
- optional side-room modules on each cardinal axis
- simple room dressing by relative offsets
- deterministic scatter of site-only decoration props
- entry paths, exterior ruin scatter, and broken wall gaps
- dev-mode generation logging with profile, seed, room, module count, chest, and defender summary

The site seed is derived from site identity, creation tick, tile, site part, and profile hash. That keeps a given generated site stable after creation while still allowing separate sites to vary.

## Debug Actions

Dev mode exposes the following actions under `MFVanilla - Arcane Sites`:

- `Spawn Arcane Cache Site Near Current Map`
- `Spawn Sealed Vault Site Near Current Map`
- `Spawn Ruined Sanctum Site Near Current Map`
- `Offer Arcane Cache Mission`
- `Offer Sealed Vault Mission`
- `Offer Ruined Sanctum Mission`
- `Spawn Arcane Cache Showcase Near Current Map`
- `Remove Bare Empty Sites`

Use the offer actions when validating the real player-facing incident path. Use direct spawn actions when testing map generation and profile layout quickly.

## Validation Checklist

- Incident can fire or be offered from a player home map.
- World site appears within the configured distance band.
- Arrival letter and site label match the mission type.
- Map generation produces the expected profile, chest, defenders, entry path, and ruins.
- Defenders are hostile, pathable, and appropriate for the threat tier.
- Chest reward opens correctly and remains stable across save/load.
- Leaving the map resolves the site normally.
- Unvisited sites expire after their registered timeout and send a neutral lost-site letter.
- A save/load cycle preserves outstanding expiry tracking.
- A second mission of the same site type cannot be active at the same time.
