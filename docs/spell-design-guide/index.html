MagicFramework Spell Design Guide

MagicFramework spells are RimWorld XML defs built from targeting rules, costs, requirements, reusable resources, and composable action trees. Start with one of the small examples, then move into the reference sections when you need more control.

First Direct Spell

Minor Heal

A direct spell validates a target, pays costs, and runs actions immediately against that target. This example heals an allied pawn and allows self-casting.

File Placement

Where It Goes

Place the spell XML under `YourMod/Defs/SpellDefs/Example_MinorHeal.xml`. Put the icon under `YourMod/Textures/UI/Gizmos/Spells/Example_MinorHeal.png`.

Dependencies

What It Requires

Depend on `oracle.magicframework`. If you reuse MFVanilla metadata or research defs, also depend on `oracle.mfvanilla`.

<MagicFramework.Definitions.SpellDef>
  <defName>Example_MinorHeal</defName>
  <label>minor heal</label>
  <description>Restores a small amount of health to an allied pawn.</description>
  <range>12</range>
  <castTimeTicks>25</castTimeTicks>

  <meta>
    <tier>1</tier>
    <elements>
      <li>MF_Element_Life</li>
    </elements>
    <domains>
      <li>MF_Domain_Vitalism</li>
    </domains>
    <disciplines>
      <li>MF_Discipline_Healing</li>
    </disciplines>
    <tags>
      <li>MF_Tag_Beneficial</li>
    </tags>
  </meta>

  <learning>
    <canBeLearned>true</canBeLearned>
    <requirements>
      <li Class="MagicFramework.Definitions.ArcaneGiftRequirementDef" />
    </requirements>
  </learning>

  <targeting>
    <shape>Single</shape>
    <primaryTargetType>Pawn</primaryTargetType>
    <pawnAffinity>Ally</pawnAffinity>
    <includePawns>true</includePawns>
    <includeBuildings>false</includeBuildings>
    <includeItems>false</includeItems>
    <allowSelfTarget>true</allowSelfTarget>
    <requireLineOfSight>true</requireLineOfSight>
    <range>12</range>
  </targeting>

  <requirements>
    <li Class="MagicFramework.Definitions.ManaRequirementDef">
      <amount>6</amount>
    </li>
    <li Class="MagicFramework.Definitions.CooldownRequirementDef">
      <cooldownTicks>120</cooldownTicks>
    </li>
  </requirements>

  <costs>
    <li Class="MagicFramework.Definitions.ManaCostDef">
      <amount>6</amount>
    </li>
    <li Class="MagicFramework.Definitions.CooldownCostDef">
      <cooldownTicks>120</cooldownTicks>
    </li>
  </costs>

  <actions>
    <li Class="MagicFramework.Definitions.SequenceActionDef">
      <actions>
        <li Class="MagicFramework.Definitions.EffectActionDef">
          <effectDef>PsycastPsychicEffect</effectDef>
          <locationSource>CurrentTarget</locationSource>
          <attachToTarget>true</attachToTarget>
        </li>
        <li Class="MagicFramework.Definitions.HealActionDef">
          <amount>10</amount>
        </li>
      </actions>
    </li>
  </actions>
</MagicFramework.Definitions.SpellDef>

Change `HealActionDef.amount` for strength, `targeting.range` for reach, and the mana/cooldown requirement and cost pairs for balance.

Next StepWhat To Add
Research gateAdd `learning.researchPrerequisites`, such as `MFV_Vitalism` when depending on MFVanilla.
Caster gateAdd `ArcaneGiftRequirementDef` and optional `CasterLevelRequirementDef` under `learning.requirements`.
Generated detailsAdd `{MF:SpellSummary}` or `{MF:Effects}` to the description so mechanics stay current.
Healing scalingAdd `power.casterLevelFactor` and `scaledAttributes` with `Healing`.
Self-only variantUse `targeting.useCasterAsTarget` to cast without opening a target prompt.

First Projectile Spell

Ember Bolt

Projectile spells launch an authored projectile now and run `onImpactActions` later. Put hit-dependent effects under `onImpactActions`, not beside the projectile action.

Flow

Launch Now

The cast validates and pays costs, plays its cast effect, then launches a real RimWorld projectile from `launchOrigin` to `targetSource`.

Impact

Payload Later

`onImpactActions` run after impact, shield block, destruction, explosion landing, or timeout. Use `CurrentTarget` for the hit thing and `CurrentCell` for the impact location.

<li Class="MagicFramework.Definitions.LaunchProjectileActionDef">
  <projectileDef>Bullet_Revolver</projectileDef>
  <launchOrigin>Caster</launchOrigin>
  <targetSource>CurrentTarget</targetSource>
  <onImpactActions>
    <li Class="MagicFramework.Definitions.EffectActionDef">
      <effectDef>GiantExplosion</effectDef>
      <soundDef>Explosion_Flame</soundDef>
      <locationSource>CurrentTarget</locationSource>
      <attachToTarget>true</attachToTarget>
    </li>
    <li Class="MagicFramework.Definitions.DamageActionDef">
      <amount>12</amount>
      <damageDef>Flame</damageDef>
    </li>
  </onImpactActions>
</li>

`MF_Firebolt` in MF Vanilla is the production version of this pattern. It adds research, caster level requirements, debug labels, spell power scaling, and tuning.

FieldWhat It Controls
`projectileDef`A `ThingDef` whose `thingClass` is a RimWorld projectile, such as `Bullet_Revolver`.
`launchOrigin`Where the projectile starts: `Caster`, `CurrentTarget`, or `CurrentCell`.
`targetSource`What the projectile aims at: `CurrentTarget`, `CurrentCell`, or `Caster`.
`preventFriendlyFire`Passes friendly-fire prevention into vanilla projectile launch where vanilla supports it.
`onImpactActions`Child actions that run after projectile resolution. Put hit-dependent effects here.
VariantWhat To Add
Burn riderAdd `ApplyHediffActionDef` with `hediffDef` `Burn` under `onImpactActions`.
Small blastAdd `ExplosionActionDef` under `onImpactActions` and use `CurrentCell` for impact visuals.
ScalingAdd `power.casterLevelFactor` and `scaledAttributes` such as `Damage`, `Cooldown`, and optionally `Radius`.
Resource discoverySearch RimWorld `Data` defs and MFVanilla spell XML for `projectileDef`, `effectDef`, `soundDef`, `damageDef`, and `hediffDef` examples.

Core Mental Model

Direct Versus Projectile Actions

Use a direct action when the effect should happen as soon as the cast completes. Use projectile impact actions when the effect should wait for vanilla projectile resolution.

Direct

Immediate Payload

`HealActionDef`, direct `DamageActionDef`, and most simple buffs run against the current target as soon as the spell executes.

Projectile

Impact Payload

`LaunchProjectileActionDef` stores its child payload under `onImpactActions` so effects happen only after the projectile reports an impact result.

Reference

SpellDef Anatomy

FieldPurpose
`defName`Stable unique identifier used by saves, references, generated scrolls, and other defs.
`label`Player-facing spell name.
`description`Player-facing description. Can include generated detail tokens such as `{MF:SpellSummary}`.
`range`Default display and legacy range. Also set `targeting.range` for validation clarity.
`castTimeTicks`Warmup duration before execution. `60` ticks is one in-game second.
`gizmoIconPath`Texture path under `Textures`, without the file extension.
`meta`Tier, elements, domains, disciplines, and tags for display and rule matching.
`learning`Research and requirement gates for acquiring the spell.
`targeting`Initial player targeter policy.
`requirements`Cast-time checks such as mana, cooldown, Arcane gift, and caster level.
`costs`Resources or state applied after validation succeeds.
`actions`The execution tree that performs spell effects.
