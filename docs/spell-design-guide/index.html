MagicFramework Spell Design Guide

MagicFramework spells are RimWorld XML defs built from targeting rules, costs, requirements, reusable resources, and composable action trees. Start with one of the small examples, then move into the reference sections when you need more control.

Design Workflow

Design The Spell Before Writing XML

Good MagicFramework spells start as a gameplay decision, then become XML. Decide what the player is allowed to do, when the effect happens, how the spell is paid for, and what state must survive save/load before you pick individual actions.

  1. Pick the role.
    Is this damage, rescue, control, infrastructure, a maintained defense, a delayed trap, or a summoned helper?
  2. Choose delivery.
    Use direct actions for immediate effects, projectiles for travel and impact timing, target queries for area/chain effects, and persistent actions for anything that remains on the map.
  3. Set target policy.
    Choose pawn/cell/thing targeting, affinity, self-cast behavior, line of sight, range, and terrain restrictions before balancing numbers.
  4. Pair checks and costs.
    Requirements explain why the cast cannot happen; costs spend resources after validation succeeds. Mana and cooldown usually need both sides.
  5. Plan scaling.
    Use lightweight `scaledAttributes` for normal growth. Use explicit `ScalableFloatDef` or scalar fields when one number needs special tuning.
  6. Design cleanup.
    Any delayed, repeated, summoned, spawned, maintained, wall, field, or area effect should have clear expire/remove/break behavior.
  7. Explain mechanics.
    Keep lore readable, then add generated tokens such as `{MF:SpellSummary}` so details stay current as tuning changes.

Useful mental split: targeting controls the initial player selection. Actions can later retarget through queries, chains, child contexts, projectile impact context, or persistent lifecycle callbacks.

Targeting Reference

Targeting Compatibility

Targeting fields are cumulative. If a spell enables more than one category, terrain gate, or special requirement, all relevant checks must pass. This is powerful, but it can also make a spell impossible to cast if the fields describe different target kinds.

Categories

Thing Types

`includePawns`, `includeBuildings`, and `includeItems` decide which thing types can be selected or affected.

Cells

Location Gates

`requireStandableCell`, `requireWalkableCell`, and `requireWaterCell` validate the target location.

Selection

Initial Target

`allowSelfTarget`, `useCasterAsTarget`, and `requireLineOfSight` change how the first target is chosen.

Special

Framework Cases

`requireResurrectableCorpse` narrows targeting to corpse-style spells and should be paired deliberately.

Spell IntentPrimary TargetCategoriesRequirements And Notes
Ally heal`Pawn`Pawns only`pawnAffinity` `Ally`; `allowSelfTarget` only if the caster may heal themselves.
Self buff`Pawn`Pawns onlyPrefer `useCasterAsTarget=true` when no target prompt is needed.
Hostile bolt`Pawn` or `PawnOrThing`Pawns, optionally Buildings/Items`requireLineOfSight=true`; avoid `allowSelfTarget`.
Area burst`PawnOrCell`Categories describe what later queries or payloads may affectCell requirements are optional unless the cast location must be special terrain.
Summon or placement spell`Cell`Categories usually irrelevantUse `requireWalkableCell` or `requireStandableCell` for placement safety.
Water-only spell`Cell` or `PawnOrCell`Depends on payload`requireWaterCell=true`; combine with walkable/standable only if all gates should be required.
Resurrection`Thing`Items only`requireResurrectableCorpse=true`; disable Pawns and Buildings.

Suspicious combinations: `Pawn` targets with Pawns disabled, `Thing` targets with Buildings and Items both disabled, corpse requirements with non-Thing targeting, corpse targeting with `useCasterAsTarget`, self-targeting while Pawns are disabled, and water-cell requirements combined with walkable or standable gates without testing.

First Direct Spell

Minor Heal

A direct spell validates a target, pays costs, and runs actions immediately against that target. This example heals an allied pawn and allows self-casting.

File Placement

Where It Goes

Place the spell XML under `YourMod/Defs/SpellDefs/Example_MinorHeal.xml`. Put the icon under `YourMod/Textures/UI/Gizmos/Spells/Example_MinorHeal.png`.

Dependencies

What It Requires

Depend on `oracle.magicframework`. If you reuse MFVanilla metadata or research defs, also depend on `oracle.mfvanilla`.

<?xml version="1.0" encoding="utf-8" ?>
<Defs>
<MagicFramework.Definitions.SpellDef>
  <defName>Example_MinorHeal</defName>
  <label>minor heal</label>
  <description>Restores a small amount of health to an allied pawn.

{MF:SpellSummary}</description>
  <gizmoIconPath>UI/Gizmos/Spells/Example_MinorHeal</gizmoIconPath>
  <range>12</range>
  <castTimeTicks>25</castTimeTicks>

  <meta>
    <tier>1</tier>
    <elements>
      <li>MF_Element_Life</li>
    </elements>
    <domains>
      <li>MF_Domain_Vitalism</li>
    </domains>
    <disciplines>
      <li>MF_Discipline_Healing</li>
    </disciplines>
    <tags>
      <li>MF_Tag_Beneficial</li>
    </tags>
  </meta>

  <learning>
    <canBeLearned>true</canBeLearned>
    <requirements>
      <li Class="MagicFramework.Definitions.ArcaneGiftRequirementDef" />
    </requirements>
  </learning>

  <targeting>
    <shape>Single</shape>
    <primaryTargetType>Pawn</primaryTargetType>
    <pawnAffinity>Ally</pawnAffinity>
    <includePawns>true</includePawns>
    <includeBuildings>false</includeBuildings>
    <includeItems>false</includeItems>
    <allowSelfTarget>true</allowSelfTarget>
    <requireLineOfSight>true</requireLineOfSight>
    <range>12</range>
  </targeting>

  <requirements>
    <li Class="MagicFramework.Definitions.ManaRequirementDef">
      <amount>6</amount>
    </li>
    <li Class="MagicFramework.Definitions.CooldownRequirementDef">
      <cooldownTicks>120</cooldownTicks>
    </li>
  </requirements>

  <costs>
    <li Class="MagicFramework.Definitions.ManaCostDef">
      <amount>6</amount>
    </li>
    <li Class="MagicFramework.Definitions.CooldownCostDef">
      <cooldownTicks>120</cooldownTicks>
    </li>
  </costs>

  <actions>
    <li Class="MagicFramework.Definitions.SequenceActionDef">
      <actions>
        <li Class="MagicFramework.Definitions.EffectActionDef">
          <effectDef>PsycastPsychicEffect</effectDef>
          <locationSource>CurrentTarget</locationSource>
          <attachToTarget>true</attachToTarget>
        </li>
        <li Class="MagicFramework.Definitions.HealActionDef">
          <amount>10</amount>
        </li>
      </actions>
    </li>
  </actions>
</MagicFramework.Definitions.SpellDef>
</Defs>

Change `HealActionDef.amount` for strength, `targeting.range` for reach, and the mana/cooldown requirement and cost pairs for balance.

Next StepWhat To Add
Research gateAdd `learning.researchPrerequisites`, such as `MFV_Vitalism` when depending on MFVanilla.
Caster gateAdd `ArcaneGiftRequirementDef` and optional `CasterLevelRequirementDef` under `learning.requirements`.
Generated detailsAdd `{MF:SpellSummary}` or `{MF:Effects}` to the description so mechanics stay current.
Healing scalingAdd `power.casterLevelFactor` and `scaledAttributes` with `Healing`.
Self-only variantUse `targeting.useCasterAsTarget` to cast without opening a target prompt.

Common mistakes: setting only top-level `range`, adding a mana cost without a matching mana requirement, or leaving `pawnAffinity` as `All` on a beneficial spell. The targeter should make the safe intent obvious.

First Projectile Spell

Ember Bolt

Projectile spells launch an authored projectile now and run `onImpactActions` later. Put hit-dependent effects under `onImpactActions`, not beside the projectile action.

Flow

Launch Now

The cast validates and pays costs, plays its cast effect, then launches a real RimWorld projectile from `launchOrigin` to `targetSource`.

Impact

Payload Later

`onImpactActions` run after impact, shield block, destruction, explosion landing, or timeout. Use `CurrentTarget` for the hit thing and `CurrentCell` for the impact location.

<li Class="MagicFramework.Definitions.LaunchProjectileActionDef">
  <projectileDef>Bullet_Revolver</projectileDef>
  <launchOrigin>Caster</launchOrigin>
  <targetSource>CurrentTarget</targetSource>
  <onImpactActions>
    <li Class="MagicFramework.Definitions.EffectActionDef">
      <effectDef>GiantExplosion</effectDef>
      <soundDef>Explosion_Flame</soundDef>
      <locationSource>CurrentTarget</locationSource>
      <attachToTarget>true</attachToTarget>
    </li>
    <li Class="MagicFramework.Definitions.DamageActionDef">
      <amount>12</amount>
      <damageDef>Flame</damageDef>
    </li>
  </onImpactActions>
</li>

`MF_Firebolt` in MF Vanilla is the production version of this pattern. It adds research, caster level requirements, debug labels, spell power scaling, and tuning.

If `projectileDef` is missing or not a RimWorld projectile, MagicFramework logs a warning and runs `onImpactActions` immediately. That fallback prevents a dead spell, but it means the XML should be fixed.

FieldWhat It Controls
`projectileDef`A `ThingDef` whose `thingClass` is a RimWorld projectile, such as `Bullet_Revolver`.
`launchOrigin`Where the projectile starts: `Caster`, `CurrentTarget`, or `CurrentCell`.
`targetSource`What the projectile aims at: `CurrentTarget`, `CurrentCell`, or `Caster`.
`preventFriendlyFire`Passes friendly-fire prevention into vanilla projectile launch where vanilla supports it.
`onImpactActions`Child actions that run after projectile resolution. Put hit-dependent effects here.
VariantWhat To Add
Burn riderAdd `ApplyHediffActionDef` with `hediffDef` `Burn` under `onImpactActions`.
Small blastAdd `ExplosionActionDef` under `onImpactActions` and use `CurrentCell` for impact visuals.
ScalingAdd `power.casterLevelFactor` and `scaledAttributes` such as `Damage`, `Cooldown`, and optionally `Radius`.
Resource discoverySearch RimWorld `Data` defs and MFVanilla spell XML for `projectileDef`, `effectDef`, `soundDef`, `damageDef`, and `hediffDef` examples.

Friendly-fire caution: `pawnAffinity` controls the initial target. Explosions, radius queries, chains, and child actions need their own affinity and include/exclude choices.

Core Mental Model

Direct Versus Projectile Actions

Use a direct action when the effect should happen as soon as the cast completes. Use projectile impact actions when the effect should wait for vanilla projectile resolution.

Direct

Immediate Payload

`HealActionDef`, direct `DamageActionDef`, and most simple buffs run against the current target as soon as the spell executes.

Projectile

Impact Payload

`LaunchProjectileActionDef` stores its child payload under `onImpactActions` so effects happen only after the projectile reports an impact result.

Reference

SpellDef Anatomy

FieldPurpose
`defName`Stable unique identifier used by saves, references, generated scrolls, and other defs.
`label`Player-facing spell name.
`description`Player-facing description. Can include generated detail tokens such as `{MF:SpellSummary}`.
`range`Default display and legacy range. Also set `targeting.range` for validation clarity.
`castTimeTicks`Warmup duration before execution. `60` ticks is one in-game second.
`gizmoIconPath`Texture path under `Textures`, without the file extension.
`meta`Tier, elements, domains, disciplines, and tags for display and rule matching.
`learning`Research and requirement gates for acquiring the spell.
`targeting`Initial player targeter policy.
`requirements`Cast-time checks such as mana, cooldown, Arcane gift, and caster level.
`costs`Resources or state applied after validation succeeds.
`actions`The execution tree that performs spell effects.

Action Catalog

Actions are composable XML nodes under `actions`, `onImpactActions`, query child actions, or lifecycle callbacks. Start with the smallest action that expresses the spell, then add child lists only when timing or targeting actually changes.

FamilyAction DefsUse When
Flow`SequenceActionDef`, `DelayActionDef`, `RepeatActionDef`, `ConditionalActionDef`, `LogMessageActionDef`You need ordered steps, delayed payloads, repeating pulses, branching logic, or dev diagnostics.
Presentation`EffectActionDef`, `ProceduralFXActionDef`You need explicit RimWorld effecters/sounds or framework procedural magic visuals.
Direct Effects`DamageActionDef`, `HealActionDef`, `ApplyHediffActionDef`, `RemoveHediffActionDef`, `StunActionDef`, `ExtinguishFireActionDef`, `TemperaturePushActionDef`You are changing a pawn, thing, fire, or local temperature immediately in the current context.
Area & Queries`ExplosionActionDef`, `ApplyToTargetsActionDef`, `ApplyChainTargetsActionDef`, `ChainLightningActionDef`You need area damage, secondary targets, deterministic chain behavior, or child actions over queried targets.
Movement`TeleportActionDef`, `KnockbackActionDef`, `PullActionDef`, `MovePawnTowardPointActionDef`, `MoveStoneChunksActionDef`You are moving pawns, things, or stone chunks and need collision or destination rules.
Projectiles`LaunchProjectileActionDef`The effect should wait for vanilla projectile travel, impact, shield block, destruction, or timeout.
Persistent`PersistentEffectActionDef`, `PersistentAreaZoneActionDef`, `PersistentWallZoneActionDef`, `ProximityTriggerActionDef`, `ApplyForceFieldActionDef`Something remains in the world and needs save/load-aware cleanup or lifecycle callbacks.
Summon & Spawn`SummonPawnActionDef`, `SpawnThingActionDef`, `TerrainPatchActionDef`, `DestroyThingActionDef`, `ResurrectPawnActionDef`The spell creates, changes, restores, or removes world state beyond a simple hediff or damage event.
Stats & Status`ApplyStatModifierActionDef`, `SustainedStatModifierActionDef`, `ClearStatModifiersActionDef`, `TimedStatusEffectActionDef`, `ApplyStatusEffectActionDef`You need buff/debuff identity, stat modification, visible status cues, or refresh behavior.

Generated Presentation

Description Tokens

Use generated text for mechanics, not lore. Keep the first sentence readable, then add one or two tokens so balancing changes do not leave stale descriptions behind.

TokenUse
`{MF:SpellSummary}`Compact combined summary for spell details.
`{MF:Effects}`Generated action/effect summary.
`{MF:ManaCost}`Resolved mana cost text.
`{MF:Cooldown}`Cooldown text.
`{MF:Range}`Targeting range text.
`{MF:Requirements}`Cast and learning requirement text.
`{MF:PowerScaling}`Power and scaling summary when authored.

Before Release

Validation Checklist

MagicFramework can express a lot of behavior in XML, so validation needs to cover more than “the button appears.” Test normal use, failure cases, and cleanup.

AreaCheck
XML loadStart RimWorld and confirm no unresolved class, defName, enum, texture, or XML structure errors.
LearningVerify research gates, Arcane Gift, caster level, scroll recipes, and hidden/unhidden behavior.
TargetingTest valid targets, invalid targets, self-target rules, line of sight, terrain requirements, range boundaries, and hostile/ally filtering.
CostsConfirm mana and cooldown requirements fail clearly, then costs apply only after accepted casts.
ActionsCheck direct effects, projectile impact effects, query child actions, scaling, and generated description text against real gameplay.
PersistenceSave/load while delays, repeats, summons, walls, areas, fields, triggers, and maintained effects are active.
CleanupDown or kill the caster, remove the target, leave the map, expire the effect, recast it, and confirm no orphaned state remains.
PresentationVerify icon path, gizmo label, generated details, sound/effect defs, and dev/debug labels are readable.
